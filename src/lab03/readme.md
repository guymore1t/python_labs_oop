# Лабораторная работа №3
## Наследование и иерархия классов

### Цель
- Освоить механизм наследования классов.
- Научиться строить иерархию объектов на основе класса `Ticket`.
- Понять разницу между базовым и производными классами.
- Переиспользовать код через `super()`.
- Освоить переопределение методов и полиморфизм.

---

### Реализованная иерархия

**Базовый класс:** `Ticket` (из ЛР-1)  
Хранит маршрут, цену, статус и уникальный номер.  
Методы: `sell()`, `use()`, `refund()`, `__str__()`.

**Производные классы:**

1. **`SingleTicket`** – разовый билет с указанием места.  
   *Новые атрибуты:* `seat_number` (номер места), `_valid` (действительность).  
   *Новый метод:* `validate()` – проверяет, можно ли ещё использовать билет.  
   *Переопределённые методы:*  
   - `use()` – дополнительно проверяет `_valid` и выводит номер места.  
   - `__str__()` – добавляет информацию о месте и действительности.

2. **`ReturnTicket`** – билет туда-обратно.  
   *Новые атрибуты:* `return_route` (обратный маршрут), `return_price` (цена обратного билета), флаги `_outbound_used` и `_return_used`.  
   *Новый метод:* `calculate_total_price()` – возвращает сумму цен прямого и обратного рейсов.  
   *Переопределённые методы:*  
   - `use()` – работает в два этапа: сначала используется прямой рейс, затем обратный, после чего статус меняется на `used`.  
   - `__str__()` – показывает оба маршрута и состояние каждого рейса.

### Три сценария работы с иерархией

**Сценарий А: Продажа всех доступных разовых билетов**  
Обходим коллекцию, для каждого разового билета со статусом `available` вызываем `sell()`.

**Сценарий Б: Подсчёт общей стоимости всех билетов**  
Для обычных билетов берём цену `price`, для билетов туда-обратно используем `calculate_total_price()`, суммируем.

**Сценарий В: Проверка валидности и пересоздание недействительных разовых билетов**  
Если разовый билет недействителен (`validate() == False`), создаётся новый такой же и добавляется в коллекцию.

### Вывод
- Научились строить иерархию классов с переиспользованием кода через `super()`.
- Освоили переопределение методов: один и тот же метод `use()` ведёт себя по‑разному в `SingleTicket` и `ReturnTicket`.
- Поняли полиморфизм – возможность вызывать общий метод без проверок `if type == ...`, а просто `obj.use()`.
- Коллекция из ЛР-2 без изменений работает с производными классами, что доказывает корректность наследования.
